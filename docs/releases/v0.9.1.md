# v0.9.1 — The QR arrives in seconds, and sessions file themselves

**Download `photobooth-v0.9.1-win-x64.zip`, unzip, run `Photobooth.Server.exe`.**
Nothing to install — no .NET, no Node.

Then open <http://localhost:5000/operator>.

The test sheet is **[docs/FIELD-TEST.md](../FIELD-TEST.md)**, unchanged from
v0.8.0. Nothing below affects the camera, so there is nothing to re-run.

## Fixed since v0.9.0

### The QR was taking 17 seconds, and almost none of it was uploading

Three photos upload in about 9 seconds, so a single file is ~3s and the real work
before a link exists is ~4s. The other fourteen seconds was the booth **doing
nothing**: a finished session was written to disk and then left until the upload
queue's fifteen-second poll came round to notice it.

The queue is now poked the moment a session is ready. Measured on a real account:
the time from a session being archived to its first upload attempt went from
**13.3 seconds to 7 milliseconds**.

Raw photos also upload three at a time rather than one after another, which takes
the tail of a session from ~9s to ~3s.

### A published session could be marked as failed

`session.json` was overwritten in place while the console read it — and both
screens poll the delivery status every three seconds, which reads every session's
record. On Windows that collision throws a sharing violation, and the queue read
it as a failed upload, then retried a session that had in fact just published
perfectly well.

Records are now written to a temporary file and moved into place. That also stops
a reader catching the file mid-write and silently dropping a session from the
console's list.

### Sessions are filed under one folder in Drive

Every session still gets **its own folder**; those folders now sit inside a
single **`Photobooth`** folder rather than loose in the root of My Drive, which
one event turns into a hundred folders strewn through it. Rename it in
**Setup → Guest delivery**.

```
My Drive
└─ Photobooth
   ├─ 2026-09-08_1059_oyivfw    strip.jpg + the raw photos
   └─ 2026-09-08_1104_gihnpn    strip.jpg + the raw photos
```

> If photos ever look like they are **not** in folders: Drive opens on a **Home**
> tab that lists recent files flat, whatever folder they are in. Click **My
> Drive** in the sidebar.

The app creates that folder itself. `docs/DRIVE-SETUP.md` previously suggested
making one by hand and pasting its id, which **could never have worked** — the
`drive.file` scope reaches only files the app created. That advice is gone.

## Still true

- **Google Drive is off in this build.** No account is configured, nothing is
  uploaded, and the guest screen says to ask for the photos. You need no Google
  account and no internet connection for any test in the field sheet. Turning it
  on is [docs/DRIVE-SETUP.md](../DRIVE-SETUP.md), per machine.
- **The app cannot fire the shutter.** The countdown is advisory: the guest sees
  "3-2-1" and you press the remote.
- **Everything about the camera is still an assumption.** File naming,
  extensions, timings — none of it has met a real R50.

## The one thing we most need to know

**Does the BR-E1 remote work while the camera is USB-tethered?** Canon's own
advice is to disable Bluetooth before connecting USB, which is the opposite of
what the remote needs. Test 1 covers it. If they conflict, the fallback is the
camera's own shutter button and nothing else in the design changes.

## Upgrading from v0.9.0

Unzip alongside the old folder rather than over it, then copy across:

- `data/` — past sessions, your settings, any backdrop image, and the Drive
  sign-in if you have one
- `templates/` — any frame you made in the editor

Both live next to the .exe, so a fresh unzip will not have them.

Sessions already in Drive stay where they are; only new ones go into the
`Photobooth` folder. Their links keep working.

## Notes

- Windows SmartScreen will warn about an unsigned binary. *More info → Run anyway*.
- You need a **DR-E18 / LP-E17 dummy battery**: the R50 will not power itself over
  USB-C while tethered.
- The version string is at the foot of the left-hand rail; include it with any
  result.
- 179 automated tests pass. None of them involve a camera — that is what the
  field test is for.
