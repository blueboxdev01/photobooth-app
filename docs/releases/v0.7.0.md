# v0.7.0 — Operator console, layout settings, output folder

**Download `photobooth-v0.7.0-win-x64.zip`, unzip, run `Photobooth.Server.exe`.**
Nothing to install — no .NET, no Node.

Then open <http://localhost:5000/operator>.

The test sheet is **[docs/FIELD-TEST.md](../FIELD-TEST.md)**, also in the ZIP, and
has been updated for the new interface.

## New since v0.6.0

### A proper console

Everything is now one dashboard: a fixed rail on the left holding the session
controls and navigation, and the work on the right. **Session**, **Templates**
and **Setup** all live in the same frame.

The session state is the largest thing on the screen on purpose — this is glanced
at across a booth while talking to a guest, not studied.

**Light and dark**, with the switch at the foot of the rail. A booth gets set up
in daylight and run in a dark room; use whichever is easier on your eyes. It
defaults to following Windows.

The **guest display is deliberately unaffected** by that switch — it is
full-bleed and carries the event's own backdrop.

### Photos per strip, placed for you

**Setup → Strip layout.** Choose an output size and how many photos, and the
slots are placed evenly — equal sizes, equal gaps, a footer band left clear for
branding.

The **shape decides the arrangement**: a portrait size stacks photos into a
strip, a landscape one runs them along a row and then into a grid rather than
shrinking faces to slivers. Minimum and maximum bound what the event allows.

You can still drag individual slots in **Templates** afterwards.

> Changing the size or photo count re-lays the slots out, which **detaches frame
> art** drawn for the old shape. The PNG stays on disk and can be re-attached in
> the editor. Left attached it would be stretched over the new layout.

### An output folder you can find

**Setup → Folders** now has two, and they must be different:

| | |
|---|---|
| **Watch folder** | Wherever EOS Utility saves. Every guest's raw frames land here together |
| **Output folder** | Finished sessions, **one folder per guest**, holding the raw photos, the strip and a `session.json` |

This always worked, but the output folder was buried inside the application
directory and could only be changed by editing JSON — so it looked as though
sessions were not being separated at all. Point it somewhere findable, such as
`C:\Users\you\Pictures\PhotoboothSessions`.

### Event backdrop

**Setup → Guest display** sets a colour and an optional image behind the guest
screen, so the booth can match an event.

## Still true

- **No uploading.** Google Drive is not in this build. Photos stay in the output
  folder on your machine.
- **The app cannot fire the shutter.** The countdown is advisory: the guest sees
  "3-2-1" and you press the remote.
- **Everything about the camera is still an assumption.** File naming,
  extensions, timings — none of it has met a real R50. Contradicting it is the
  point of the exercise.

## The one thing we most need to know

**Does the BR-E1 remote work while the camera is USB-tethered?** Canon's own
advice is to disable Bluetooth before connecting USB, which is the opposite of
what the remote needs. Test 1 covers it. If they conflict, the fallback is the
camera's own shutter button and nothing else in the design changes.

## Upgrading from v0.6.0

Unzip alongside the old folder rather than over it, then copy across:

- `data/` — past sessions, your settings and any backdrop image
- `templates/` — any frame you made in the editor

Both live next to the .exe, so a fresh unzip will not have them.

## Sending results back

**Setup → Download diagnostics bundle.** Logs, every ingest decision with its
reason, the effective settings, and the exact commit. **It contains no
photographs** — if a particular photo matters, send that one deliberately.

## Notes

- Windows SmartScreen will warn about an unsigned binary. *More info → Run anyway*.
- You need a **DR-E18 / LP-E17 dummy battery**: the R50 will not power itself over
  USB-C while tethered.
- The version string is at the foot of the left-hand rail; include it with any
  result.
